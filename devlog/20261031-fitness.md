# Fitness of the framework against the use cases

Kept current as rungs land. Columns are the kernel capabilities each use case needs;
cells say what exists. Updated 2026-11-01 after M2.

Capabilities: **clk** multi-rate deterministic clock · **led** ledgers that close ·
**log** replay and fork · **man** manifest as document · **fld** fields on real grids ·
**net** networks · **pop** populations and cohorts · **agt** agents · **rul** rules and
calendar · **haz** hazards · **ens** ensembles and job runner · **reg** registry ·
**sco** scoreboards and hindcast · **nst** nested scales · **fac** facade

Reading after M2: six of fifteen capabilities exist for every row (clock, ledgers,
log, manifest, fields, registry). The planetary and IPCC forks need only the global
grid to start, which is a grid implementation, not a kernel change. The rows that
diverge earliest remain Hormuz and grid-and-heat, which need networks and hazards before
more fields matter.
